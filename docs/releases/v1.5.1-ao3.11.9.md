# CrossInk AO3.11.9

AO3.11.9 addresses the remaining X3 update-check failure after AO3.11.8 confirmed that response size alone was not the cause.

## AO3 Request Compatibility

- Restores the browser-style `Accept` and `Accept-Language` headers used by the original AvesO3 updater.
- Uses the original Windows Chrome-style User-Agent consistently for work-page and EPUB requests.
- Tries CrossInk's certificate-verified ESP HTTPS transport first.
- If that transport fails before receiving an HTTP response, retries once through CrossInk's lower-memory wolfSSL transport before trying the alternate AO3 host.
- Successful metadata parsing still stops the full-work response early, retaining the X3 memory and latency improvement from AO3.11.8.

## Actionable Errors

The device now distinguishes:

- HTTP 403 or unsupported locked works.
- AO3 rate limiting (HTTP 429).
- Deleted or missing works (HTTP 404).
- Other HTTP response codes.
- A received page missing date or chapter metadata.
- A response ending before metadata.
- A connection or TLS failure before AO3 responds.

## Download Safety

Temporary-file download, ZIP and AO3 work-ID validation, backup, rollback, cache-preserving installation, and reading-position restoration remain unchanged. The low-memory transport is only attempted after verified HTTPS fails before receiving a response.

## Firmware

For an X3 or standard X4, flash `CrossInk-AO3-v1.5.1-ao3.11.9-x3-x4.bin`. The boot screen should report `1.5.1-ao3.11.9`.

Do not flash the X3/X4 image on X4 Pro, X4 Classic, or Sticky hardware.

## Compatibility

No AO3 reindex, cache deletion, settings reset, or archive migration is required.

## Validation

- AO3.11.7 hardware validation refreshed 198 works in 50-work batches without crashing.
- Production ESP32-C3 X3/X4 firmware compilation validates both HTTP transports and the integrated updater.
- Hardware validation is required for the live AO3 check and subsequent EPUB download.
