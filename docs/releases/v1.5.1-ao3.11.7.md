# CrossInk AO3.11.7

AO3.11.7 is an X3/X4 hotfix for the two hardware failures found while testing AO3.11.6. It retains all AO3.11.6 behavior and does not include the later CrossInk upgrade steps.

## Metadata Refresh Crash

- AO3 metadata parsing now holds the renderer lock whenever the EPUB inflater borrows framebuffer memory.
- This prevents the render task from drawing into the same memory while a work is being indexed.
- The attached X3 crash report identified this race in `GfxRenderer::drawPixel()` while `Ao3IndexActivity` displayed `Indexing 4 / 50`; it was not a 100-book limit or ordinary heap exhaustion.
- The batch limit remains 50 works.

## AO3 Chapter Updates

- Update checks now request AO3's full-work page directly.
- Explicit and chaptered works no longer rely on the HTTP client preserving AO3's adult-view cookie across a redirect to the latest chapter.
- The streamed metadata parser accepts additional attributes, multiple/reordered class names, and either quote style in AO3's statistics markup.
- Temporary-file download, EPUB/work-ID validation, backup, rollback, cache-preserving rebuild, and silent network restart are unchanged.

## Firmware

For an X3 or standard X4, flash `CrossInk-AO3-v1.5.1-ao3.11.7-x3-x4.bin`. The boot screen should report `1.5.1-ao3.11.7`.

Do not flash the X3/X4 image on X4 Pro, X4 Classic, or Sticky hardware. Those devices require their board-specific build.

## Compatibility

No AO3 reindex, cache deletion, settings reset, or archive migration is required.

## Validation

- Focused tests cover AO3 full-work URL generation and tolerant streamed metadata parsing.
- Production ESP32-C3 X3/X4 firmware compilation validates the integrated target.
- Hardware validation is still required for a live metadata refresh and AO3 chapter update.
