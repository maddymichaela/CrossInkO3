# CrossInk AO3.11.6

AO3.11.6 is an X3-focused hotfix for AO3 metadata refresh and on-device chapter updates. It retains all AO3.11.5 end-of-book behavior and does not include the later CrossInk 1.6 upgrade steps.

## Metadata Refresh

- AO3 metadata refresh no longer waits forever when the device remains below the old 80 KiB free / 48 KiB contiguous heap gate.
- Metadata-only EPUB loading temporarily lends the display framebuffer to the ZIP inflater as reusable scratch memory. The e-ink panel continues to show the existing progress screen and the framebuffer is restored before redraw.
- A genuinely unsafe low-memory state now ends on a dismissible error screen with recovery guidance instead of appearing frozen.
- The batch limit remains 50 works.

## AO3 Chapter Updates

- The AO3 HTTPS preflight now uses the same 35,000-byte free / 20,000-byte contiguous heap floor as CrossInk's established KOReader TLS client.
- This avoids rejecting normal X3 memory levels immediately after Wi-Fi starts while retaining protection against severely fragmented heap.
- Streamed metadata parsing, temporary-file download, EPUB/work-ID validation, backup, rollback, cache-preserving rebuild, and silent network restart are unchanged.

## Firmware

For an X3 or standard X4, flash `CrossInk-AO3-v1.5.1-ao3.11.6-x3-x4.bin`. The boot screen should report `1.5.1-ao3.11.6`.

Do not flash the X3/X4 image on X4 Pro, X4 Classic, or Sticky hardware. Those devices require their board-specific build.

## Compatibility

No AO3 reindex, cache deletion, settings reset, or archive migration is required.

## Validation

- Production ESP32-C3 X3/X4 firmware build passed with 388,720 bytes free in the OTA partition.
- The non-touch application audit passed.
- Focused host tests cover both metadata-refresh and AO3-TLS memory-policy boundaries. This Mac cannot execute them because its Xcode command-line SDK is unavailable; repository CI can run them.
- Hardware validation is required for live AO3 metadata refresh and AO3 HTTPS/download behavior.
