# CrossInk AO3.11.12

AO3.11.12 replaces the last generic 403 diagnosis with an AvesO3-compatible request path and endpoint-specific errors.

## Explicit Works

Explicit works are supported. AO3's adult confirmation affects its HTML work page, but it does not make a public EPUB locked. A public Explicit work should update without an AO3 account.

## AvesO3-Compatible Transport

When requesting an AO3 EPUB, CrossInkO3 now first uses the same important network behavior as AvesO3 1.4.0:

- Arduino `HTTPClient` with `NetworkClientSecure`.
- HTTP/1.1 forced through ALPN.
- Browser-style User-Agent, `Accept`, and language headers.
- Keep-alive and strict redirect handling.
- Insecure TLS certificate mode, matching AvesO3's AO3 updater.

The response body is still streamed directly to SD, avoiding a full EPUB allocation in X3 RAM. CrossInk's verified ESP HTTPS and low-memory wolfSSL transports remain available when the AvesO3-compatible client fails before receiving a response.

## Useful Errors

The updater now keeps the direct `download.archiveofourown.org` result separate from the AO3 front domains. A failure reports one of these categories:

- Direct EPUB refused with HTTP 403.
- Direct EPUB returned another HTTP status.
- Direct EPUB TLS/connection failed, followed by the fallback's HTTP status.
- No direct or fallback host could be reached.
- A downloaded EPUB did not contain matching work metadata.

## Download Safety

Temporary-file download, ZIP validation, exact work-ID matching, backup and rollback, cache-preserving installation, and reader-data preservation are unchanged.

## Grimmory and Large OPDS Feeds

OPDS feed XML is now downloaded to a temporary SD file before parsing. Closing the HTTPS connection first prevents Grimmory's 50-book **All Books** and **Recently Added** pages from growing their entry strings while the X3's TLS buffers are still live.

The OPDS browser keeps the lower-memory wolfSSL transport first and retries with CrossInk's certificate-verified ESP HTTPS transport when the first connection fails. It requests an uncompressed Atom feed and includes any received HTTP status in the error message, so authentication failures can be distinguished from TLS or interrupted-body failures. The temporary feed file is removed after every attempt.

## Firmware

For an X3 or standard X4, flash `CrossInk-AO3-v1.5.1-ao3.11.12-x3-x4.bin`. The boot screen should report `1.5.1-ao3.11.12`.

Do not flash the X3/X4 image on X4 Pro, X4 Classic, or Sticky hardware. No AO3 reindex, cache deletion, or settings reset is required.
